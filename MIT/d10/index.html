What is an Operating System?

  • An OS is system software that manages computer hardware and software resources.
  • It acts as an intermediary between the computer user and the hardware.
  • Provides a convenient and efficient environment for programs to execute.
  • Examples: Windows, Linux, macOS, Android, iOS.

Key Functions of an OS

  • Process Management: Creating, scheduling, and terminating processes.
  • Memory Management: Allocating and deallocating RAM.
  • File Management: Organizing data into files and directories.
  • I/O Management: Handling device drivers and hardware communication.
  • Security & Protection: Access control and user authentication.

Introduction to Process Management

  • A process is a program in execution. It is an active entity.
  • A program by itself is just passive code stored on disk.
  • The OS manages process creation, suspension, resumption, and synchronization.
  • Requires resources: CPU time, memory, files, and I/O devices.

Process States

  • New: The process is being created.
  • Ready: Waiting to be assigned to a processor.
  • Running: Instructions are being executed.
  • Waiting (Blocked): Waiting for some event to occur (e.g., I/O completion).
  • Terminated: The process has finished execution.

Process Control Block (PCB)

  • A data structure used by the OS to store all information about a process.
  • Also known as a Task Control Block.
  • Contains: Process State, Program Counter, CPU Registers, CPU Scheduling info, Memory-management info.
  • Crucial for Context Switching (saving the state of an old process and loading a new one).

Threads & Multithreading

  • A thread is the smallest sequence of programmed instructions managed by a scheduler.
  • Also called a "lightweight process."
  • Threads within the same process share code, data, and files, but have their own registers and stack.
  • Improves responsiveness and allows efficient resource sharing.

CPU Scheduling Concepts

  • The process of determining which process in the ready queue gets the CPU next.
  • Preemptive: OS can interrupt a running process and assign CPU to another.
  • Non-preemptive: Once a process gets the CPU, it keeps it until it terminates or blocks.
  • Goal: Maximize CPU utilization, throughput; minimize turnaround and waiting time.

Scheduling Algorithms (Part 1)

  • First-Come, First-Served (FCFS): Simplest algorithm. Process that requests CPU first gets it first. (Prone to Convoy Effect).
  • Shortest Job First (SJF): Associates with each process the length of its next CPU burst. Optimal for minimizing average waiting time.

Scheduling Algorithms (Part 2)

  • Round Robin (RR): Each process gets a small unit of CPU time (time quantum). After time is up, it is preempted and added to the end of the ready queue.
  • Priority Scheduling: A priority is associated with each process. Highest priority gets the CPU. (Prone to starvation; solved by aging).

Process Synchronization

  • When concurrent processes share data, it can result in data inconsistency.
  • Critical Section Problem: A segment of code where shared memory is accessed. No two processes should execute in their critical sections at the same time.
  • Requires mutual exclusion, progress, and bounded waiting.

Semaphores & Mutexes

  • Mutex (Mutual Exclusion): A locking mechanism to serialize access to a section of code. Only the thread that locked it can unlock it.
  • Semaphore: An integer variable used for signaling among processes. Can be binary (0/1) or counting.
  • Accessed only via two atomic operations: `wait()` and `signal()`.

Deadlocks

  • A situation where a set of processes are blocked because each process is holding a resource and waiting for another resource held by another process.
  • Result: The system grinds to a halt.
  • Classic analogy: Four cars arriving at a 4-way stop sign at the exact same time.

Deadlock: 4 Necessary Conditions

A deadlock can only occur if these 4 Coffman conditions hold simultaneously:

  • Mutual Exclusion: At least one resource is held in a non-shareable mode.
  • Hold and Wait: A process holds a resource while waiting for another.
  • No Preemption: Resources cannot be forcibly taken from a process.
  • Circular Wait: A closed chain of processes exists, each waiting for a resource held by the next.

Deadlock Handling Strategies

  • Prevention: Ensure at least one of the 4 necessary conditions cannot hold.
  • Avoidance: OS requires advance information about resources a process will request (e.g., Banker's Algorithm).
  • Detection & Recovery: Let deadlocks happen, detect them, and recover by aborting processes or preempting resources.
  • Ignorance: Pretend deadlocks never occur (used by most modern OS like Windows/Linux).

Memory Management Basics

  • Main memory (RAM) is a central repository for data and programs.
  • Programs must be brought into memory and placed within a process to be executed.
  • The OS maps logical addresses (generated by CPU) to physical addresses (actual hardware locations) via the Memory Management Unit (MMU).

Paging & Segmentation

  • Paging: Divides physical memory into fixed-size blocks (frames) and logical memory into blocks of the same size (pages). Eliminates external fragmentation.
  • Segmentation: Divides memory into variable-sized segments based on user view (e.g., main program, functions, arrays).

Virtual Memory

  • A technique that allows execution of processes that are not completely in memory.
  • Gives the illusion of a very large main memory.
  • Implemented via Demand Paging: Pages are only brought into RAM when needed.
  • Page Fault: Occurs when a process requests a page not currently in memory.

Introduction to Computer Networks

  • A system of interconnected computers and devices to share resources and data.
  • Nodes: Devices on the network (PCs, routers, servers).
  • Links: Communication pathways (cables, fiber optics, wireless).
  • Allows for communication, resource sharing (printers, storage), and centralized administration.

Network Coverage Types

  • LAN (Local Area Network): Spans a small area like a home, office, or building. High speed, low error rate (e.g., Ethernet, Wi-Fi).
  • MAN (Metropolitan Area Network): Covers a city or campus.
  • WAN (Wide Area Network): Spans large geographical areas (countries/continents). The Internet is the largest WAN.

Network Topologies

  • Star: All nodes connect to a central hub/switch. Easy to manage, but hub is a single point of failure.
  • Bus: All nodes share a single communication cable.
  • Ring: Each node connects to exactly two others.
  • Mesh: Every node connects to every other node. Highly reliable but expensive to cable.

The OSI Reference Model

A 7-layer conceptual framework for network communication:

  1. Application: Network process to application (HTTP, FTP).
  2. Presentation: Data representation and encryption.
  3. Session: Interhost communication.
  4. Transport: End-to-end connections and reliability (TCP, UDP).
  5. Network: Path determination and logical addressing (IP).
  6. Data Link: Physical addressing (MAC).
  7. Physical: Media, signal, and binary transmission.

The TCP/IP Model

  • The practical protocol suite used for the modern Internet.
  • Condenses OSI's 7 layers into 4 distinct layers:
  • 1. Application Layer (Combines OSI App, Presentation, Session)
  • 2. Transport Layer (TCP, UDP)
  • 3. Internet Layer (Maps to OSI Network layer - IP routing)
  • 4. Network Access Layer (Combines OSI Data Link and Physical)

IP Addressing (Network Layer)

  • Every device on a network needs a unique identifier.
  • IPv4: 32-bit address (e.g., 192.168.1.1). Offers about 4.3 billion addresses. Now exhausted.
  • IPv6: 128-bit address (e.g., 2001:0db8::ff00:42:8329). Created to solve IPv4 exhaustion, offering virtually infinite addresses.
  • Addresses are logical and can change depending on the network.

Routing Concepts

  • The process of selecting a path for traffic in a network.
  • Done by Routers operating at the Network Layer.
  • Routers maintain a "Routing Table" to determine where to forward packets.
  • Default Gateway: The router that traffic is sent to when the destination is not on the local network.

Routing Protocols

  • Distance Vector (e.g., RIP): Routers share their entire table with neighbors. Uses hop count. Slower convergence.
  • Link-State (e.g., OSPF): Routers map the entire network topology. Calculates shortest path using Dijkstra's algorithm. Faster and more reliable.
  • Path Vector (e.g., BGP): Used to route traffic across the global Internet between different ISPs.

Transport Layer: TCP vs UDP

  • TCP (Transmission Control Protocol): Connection-oriented. Guarantees delivery, order, and error-checking. Uses a 3-way handshake (SYN, SYN-ACK, ACK). Slower but reliable (Web, Email).
  • UDP (User Datagram Protocol): Connectionless. Sends packets without checking if they arrive. Fast but unreliable. Good for streaming, VoIP, and gaming.

Common Application Protocols

  • HTTP/HTTPS: (Port 80/443) Web browsing. HTTPS includes TLS encryption.
  • DNS (Domain Name System): (Port 53) Resolves human-readable domain names (google.com) to IP addresses.
  • SMTP/IMAP: (Port 25/143) Used for sending and retrieving emails.
  • FTP/SFTP: (Port 21/22) File Transfer Protocols.

Network Security Basics

  • Firewalls: Monitor and control incoming/outgoing network traffic based on rules.
  • VPN (Virtual Private Network): Creates a secure, encrypted tunnel over a public network.
  • Cryptography: Symmetric (same key) vs Asymmetric (Public/Private key pairs).
  • DDoS Attacks: Overwhelming a server with traffic from multiple sources to deny service.

Summary & Conclusion

  • Operating Systems: Manage hardware, provide process isolation, memory allocation, and concurrency mechanisms (deadlock handling).
  • Computer Networks: Allow disparate systems to communicate efficiently using layered architectures (OSI/TCP-IP), routing algorithms, and structured protocols.
  • Together, OS and Networks form the backbone of all modern distributed computing and cloud infrastructure.
